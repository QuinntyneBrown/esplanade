# L1 - High-Level Requirements

## L1-001: Editor Authentication and Access Recovery
The system must allow co-op board editors to authenticate with their e-mail address and password, optionally persist their session for 30 days on a trusted device, sign out, and recover access via a single-use, time-limited password reset link sent by e-mail.

## L1-002: Co-op Board Editor Invitations and Onboarding
The system must allow signed-in editors to invite additional co-op board members by e-mail with a designated board role, resend pending invitations, and allow invitees to accept a 7-day single-use invitation link by setting their full name and password.

## L1-003: Studio Overview Dashboard and Activity Monitoring
The system must provide a studio overview screen summarizing published page counts, upcoming events, waiting membership applications and inquiries, headless delivery API health, key co-op metrics, recent editor activity, and staged draft changes ready for publication.

## L1-004: Structured Page Composition and Management
The system must allow editors to list, search, filter, create, edit, and delete site pages (protecting the root `/` page from deletion), compose page content out of strongly typed, reorderable section blocks (`Hero`, `Text Block`, `Image Gallery`, `Callout`, `FAQ List`), manage page metadata and SEO descriptions, and preview the headless JSON payload.

## L1-005: News and Announcements Management
The system must allow editors to list, search, filter, create, and edit co-op news articles and announcements with headlines, short summaries, body copy, categories (`Community life`, `Governance`, `Building & accessibility`), URL slugs, featured images from the Media Library, and publication states (`Published`, `Scheduled`, `Draft`).

## L1-006: Events and Workshops Scheduling
The system must allow editors to list, search, filter, schedule, and edit co-op events and workshops with date, time range, room or location, accessibility notes, audience scope (`Open to prospective members (public)` or `Co-op members only (portal)`), RSVP capacity, and online RSVP toggles.

## L1-007: Membership Applications and Inquiries Triage
The system must provide a unified inbox for prospective co-op membership applications and general visitor inquiries submitted from the public site, allowing editors to search, filter by submission kind, inspect full applicant details, update application status (`Pending review`, `Interview scheduled`, `Approved for waitlist`, `Archived`, `Unread`), and record membership committee notes.

## L1-008: Resident Member Directory Management
The system must allow editors to list, search, filter by committee, add, and update co-op resident member profiles—including full name, suite/unit number, move-in month, e-mail address, committee role, and portal access status—exclusively for authenticated member-portal delivery.

## L1-009: Accessible Media Library Curation
The system must allow editors to browse, search, filter by media type, upload, and edit metadata for images (`JPEG`, `PNG`, `WebP`, `SVG`) and documents (`PDF`) up to 10 MB, enforcing mandatory descriptive screen-reader alt text on all images before they can be saved or attached to any content item.

## L1-010: Site Navigation and Menu Management
The system must allow editors to view, add, edit, and keyboard-reorder links in the primary header navigation menu and the footer & PDF downloads menu, pointing to internal pages, collections, or uploaded media resources.

## L1-011: Snapshot Publishing and Headless Delivery API
The system must stage content edits as drafts and allow editors to review all staged changes in a confirmation dialog, publish an atomic snapshot to the versioned headless JSON delivery API (`/v1`), record an optional release note, and trigger a configured POST webhook URL to revalidate the public site.

## L1-012: Site Identity, Scoped API Keys, and Studio Appearance
The system must allow editors to configure micro-site identity settings (site title, public domain, public contact e-mail, publish webhook URL), generate read-only delivery API keys scoped to either public content or member-portal content with one-time raw token display, and select the studio theme preference (`Match the device`, `Always light`, `Always dark`).

## L1-013: Security, Authorization, and Data Protection
The system must enforce authentication on all studio endpoints, scope headless delivery API endpoints by bearer API key permissions so resident directory data and members-only events are never exposed to public tokens, validate and sanitize all inputs against OWASP Top 10 vulnerabilities, and hash passwords and API tokens at rest.

## L1-014: Responsive Web Design and WCAG 2.2 AA Accessibility
The system must render adaptively across all viewport breakpoints—extra small (`<576px`), small (`>=576px`), medium (`>=768px`), large (`>=992px`), and extra large (`>=1200px`)—and satisfy WCAG 2.2 Level AA requirements for contrast, keyboard navigation, focus management, form error summaries, and screen-reader announcements in both light and dark themes.

## L1-015: Performance, Reliability, and Error Handling
The system must deliver low-latency API responses and fast studio page loads, provide accessible skeleton loading states, empty states, and toast/banner notifications, and present actionable recovery views for not-found (`404`), forbidden (`403`), server error (`500`), and offline network states.
