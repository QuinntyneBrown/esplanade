# Esplanade mocks

Static HTML mocks for every page, dialog and notification of the **Esplanade** headless CMS studio, in every state, in light and dark, at phone, tablet and desktop widths, with a keyboard. They are the product on disk before the product exists: what gets built is what is mocked here, and nothing more.

## How to open them

- Open [index.html](index.html) from disk for the gallery, then click any state.
- Every mock has a bar at the bottom linking its sibling states and toggling the theme (or press `t`).
- `?theme=dark` forces dark, `?theme=light` forces light. `?chrome=0` hides the mock bar and the yellow design notes so the page looks exactly like the product.
- Dialogs are shown over the page they open from; notifications on the page that triggers them. Under 640 px dialogs become bottom sheets.

## The product in one paragraph

**Esplanade** is a calm, accessible headless CMS studio built for micro-content community sites, starting with **Harbourview Co-op** (a housing co-operative for women 55+). Board volunteers sign in to compose structured **Pages** out of rich sections (hero banners, prose blocks, image galleries, callouts, FAQs), publish **News & Announcements**, schedule **Events & Workshops** with RSVP counts, review incoming **Membership Applications & Inquiries**, maintain the resident **Member Directory**, curate the **Media Library** (with required alt text for screen readers), arrange **Navigation Menus**, and publish snapshots to the headless JSON API (`api.harbourviewcoop.ca/v1`) with a single click.

## Open questions and assumptions

These are decisions the mocks make that are marked on the relevant screens with a yellow `.mock-note`:

1. **Structured section blocks over free-form HTML.** Pages are composed of ordered section blocks (`Hero`, `Text Block`, `Image Gallery`, `Callout`, `FAQ List`) rather than raw HTML, guaranteeing that the public co-op site stays accessible and consistent and the headless JSON response stays strongly typed.
2. **Explicit publish step with webhook trigger.** Saving a page, article or event stores a draft immediately; clicking **Publish changes** pushes the live snapshot to the headless delivery API and triggers the static/SSR micro-site webhook.
3. **Alt text is required on every image.** Because Harbourview Co-op serves older women and commits to WCAG 2.2 AA, uploading or saving an image in the Media Library requires descriptive alt text before it can be attached to a page or article.
4. **Membership applications & contact inquiries share one inbox.** Prospective members submitting the co-op application form and visitors sending a general question land in **Inquiries**, where the Membership Chair can filter by type, record committee notes, and update status (`Pending review`, `Interview scheduled`, `Approved`).
5. **Read-only API keys with one-time secret display.** Delivery API keys are scoped to read-only public content or member-portal content; the raw token is shown once in the creation dialog and masked thereafter.
6. **Shelfie Design System reuse.** Mocks consume `docs/design-system/tokens/tokens.css` and `docs/design-system/assets/components.css` (copied from `C:\projects\shelfie` with the violet accent and rounded system font stack preserved).
